# 🧠 Обновление v7: подход из статьи

## Что взяли из статьи и как это работает

### 1. Источники разбиты на группы (было — просто список)

| Группа | Что даёт |
|---|---|
| **техбаза** | Hacker News, Show HN, Hugging Face — что реально происходит за пределами пресс-релизов |
| **лаборатории** | Anthropic, OpenAI, Google AI, Qwen — первоисточник вместо пересказа |
| **сообщества** | r/aivideo, r/StableDiffusion, r/SunoAI, r/LocalLLaMA и др. |
| **новости** | TechCrunch, The Verge, VentureBeat, Ars Technica |
| **русскоязычное** | Хабр (ИИ, ML) |

У каждой группы своя квота (`take`) — одна лента не может забить всю выдачу. Именно это лечит однообразие: раньше 12 источников были практически одного типа.

### 2. Детект «уже у всех» — главная фича

Бот сравнивает заголовки между источниками. Если одна история всплыла в 4+ источниках — она помечается как «уже у всех» и опускается вниз списка. Наверх поднимается то, что заметил один-два источника.

Проверено на тесте: громкий релиз, который во всех лентах, ушёл вниз, а находка про новую ноду в ComfyUI и тихое поднятие лимитов в Suno — наверх.

Автор статьи делает это вручную, сверяясь с сильными каналами. Мы используем автоматический прокси — перекрытие по источникам. Не идеально, но ловит ту же суть.

### 3. Оценка тем вместо «самое горячее»

Селектор теперь оценивает по трём шкалам: пересылаемость, **можно ли попробовать руками** (максимальный вес — твоя аудитория практики), свежесть. Плюс жёсткий учёт покрытия.

### 4. Новый режим: охота за тихими изменениями

Каждый 6-й день бот не ищет релизы, а специально гуглит **смену цен, лимитов, условий доступа** у сервисов для креаторов. Про новую модель напишут все, а про то, что в Suno порезали бесплатный тариф — почти никто. Хотя это касается людей сильнее.

### 5. Жёсткий отсев и диагностика

- Новости старше **48 часов** не проходят
- Без подтверждённой даты — в мусор
- В логах GitHub Actions видно: сколько собрано по группам, сколько выброшено по возрасту, сколько без даты, **какие источники не ответили**

Последнее важно: без этого легко думать, что видишь полную картину, а половина лент просто молчит.

## Расписание на месяц

```
🎯 тема + веб-поиск  — 15 раз
📰 новость           — 10 раз
🔍 тихие изменения   —  5 раз
```

Если основной режим не сработал (нет свежих новостей / поиск пустой) — бот автоматически пробует следующий. Пустых дней не будет.

## Что сделать на GitHub

1. **Замени `bot.py`** — открой → карандашик → выдели всё → вставь новый → Commit
2. **`topics.txt` оставь как есть** — он используется
3. **Тест:** Actions → Publish AI Post → Run workflow

После запуска зайди в логи (Actions → нажми на запуск → job `publish` → шаг «Запустить бота») и посмотри блок «Диагностика сбора». Там будет видно, какие источники живые, а какие молчат.

## ⚠️ Про источники, которые могут не ответить

Часть новых лент я добавил по стандартным адресам, но проверить их из своей песочницы не мог — у меня нет доступа в открытый интернет. Особенно под вопросом: **Qwen**, **OpenAI blog**, **Google AI blog** — компании иногда меняют адреса RSS.

Это не сломает бота: мёртвая лента просто попадёт в список «не ответили» в логах, остальные отработают. После первого запуска посмотри диагностику — если что-то стабильно молчит, скажи мне название, я найду рабочий адрес или заменю источник.

GitHub Trending и Discord из статьи не добавил: у первого нет официального RSS (только сторонние зеркала, они часто отваливаются), второй вообще не отдаёт публичные ленты.

## Настройки (в начале bot.py)

| Параметр | Смысл |
|---|---|
| `FRESHNESS_HOURS = 48` | Жёсткий возраст новостей |
| `DROP_UNDATED = True` | Выбрасывать записи без даты |
| `EVERYWHERE_THRESHOLD = 4` | Со скольких источников тема считается «уже у всех» |
| `take` в каждой группе | Квота записей с ленты |
| `RECENT_TITLES_MEMORY = 20` | Глубина памяти анти-повторов |

Хочешь больше «тихих изменений»? Поменяй в `main()` условие `day % 6 == 0` на `day % 4 == 0`.

## 🧹 Фикс: болтовня Claude в постах

**Баг:** посты выходили с фразами «Вот пост для твоего канала:», «Отлично, у меня есть свежая информация. Составим пост:», «Ладно, напишу пост с фактами из поиска». Сразу видно, что писала нейросеть.

**Причина:** в режиме с веб-поиском модель комментирует свои действия между поисковыми запросами. Старый код склеивал ВСЕ текстовые блоки ответа — комментарии попадали в канал вместе с постом.

**Починено в три слоя:**

1. **Промпт** — модель обязана обернуть пост в теги `<post>…</post>`, внутри только текст поста. Явный запрет на фразы вроде «Вот пост» и «Готово».
2. **Разбор ответа** — берётся только последний текстовый блок (или блок с тегами), служебные отбрасываются. Раньше склеивались все.
3. **Чистка текста** — срезаются служебные строки сверху (по маркерам: заканчивается двоеточием + говорит про пост/поиск/данные) и хвостовые обращения к заказчику («Хочешь, могу сократить?»). Если после чистки почти ничего не осталось — пост отбраковывается, бот переключается на другой режим.

Что срезано, видно в логах строкой `🧹 Срезана болтовня: [...]` — можно контролировать, не перестарался ли фильтр.

Проверено на твоих трёх примерах: все три вычищены до первой строки поста, а нормальный пост без болтовни остаётся нетронутым.
